# 架构

## 大闭环与小闭环

- **大闭环（agent）**：需求 → 工艺窗口 → 工站方案 → 业务流与文件 → 下发 → 实测回收 → 修订建议。产出参数、文件、决定，不碰实时控制
- **小闭环（工站与执行器）**：力控、接触判定、异常中断。只接受参数配置，不接受上层实时指令
- 边界是硬的：参数进，状态出。模型只做判定和告警，执行中断由确定性阈值逻辑负责

## 仓库就是唯一真源

产品数据、模块库、工艺库、规则、术语表、决策记录都在仓库里，带版本。存在聊天和人脑里的东西，对 agent 来说等于不存在。

## 控制代码分三层

1. **业务流** `flow.yaml`：设备无关。agent 主要写这一层
2. **工站状态机** `jsdemo/statemachine.py`：按业务流调度；tier0 交接：就绪、接管、完成、异常
3. **机械臂程序**：从业务流生成，按品牌翻译。现有 URScript 生成器；以后自研臂只新增生成器

机械臂只负责到位、保持、退出。过程自由度在执行器里，机械臂的动作空间里没有扭矩这个变量。

## 宁可擦除，不要误纠

工艺模型没见过的组合返回 unknown，流水线停下来问人。决策记录缺字段就写「缺失」。这是整个系统最重要的行为约束之一。

## 测试就是验收

agent 自报完成不算。测试由人写、由控制器独立运行，全部通过才算完成。`golden.yaml` 的哈希也在测试里，防止约束被悄悄改掉。

## 数字孪生的两个版本

| 版本 | 内容 | 更新方式 |
|---|---|---|
| 设计孪生 | 流水线组合出来的方案 | 由 agent 生成，经签字 |
| 现场孪生 | 设计孪生加现场自标定和实测 | 只由自标定和实测数据更新 |

所有点位定义在治具坐标系下，现场只标定治具坐标系：误差预算（臂绝对精度 + 治具 + 基板）小于浮动批头的吸收范围时，不需要逐点找正。

## 降低现场人力

现场只做三件事：模块插到基板孔位、接标准接口、按自标定。之后测量、计算、更新、自检全部自动完成。衡量指标：每个工站的部署时长，以及人工补点次数。
